# 逻辑树卡片式重写方案

> 目标：把主宏编辑器「逻辑树」（`Gui/MacroEditGui.ahk` 的 WPF `TreeView`）重写成**卡片式扁平列表画布**——模型仍是树，视图展平为「仅展开节点」的卡片列表（深度 = 左缩进），卡片单行（图标 + 标题，结构留扩展位）。注重性能（只渲染可见节点 + 减 IPC 往返）与美观（圆角卡片 + 阴影）。

---

## 1. 现状分析

### 1.1 当前实现

「逻辑树」是 WPF `TreeView`（Name=`MacroTree`），由 `Gui/MacroEditModel.ahk` 的 `MacroTreeAdapter` 驱动：

- 模型 = 内存树 `MacroEditNode`（`id/text/icon/parent/children/checked/expanded`）。
- 视图 = 每次变更 `ClearItems + AddXamlItem` **全量重建**整棵嵌套 `<TreeViewItem>`（`Render()` + `_BuildNodeXml()`）。
- `Modify` 已对文本（`Txt_<id>`）与勾选（`ChkMark_<id>`）做增量更新；`Expand/Collapse` 走全量 Render。

### 1.2 逻辑层与视图的接缝

约 1800 行逻辑层（增删改插移 / 多选 / 调试 / 拖拽 / 右键）**全部经 `MacroTreeAdapter` 的 TreeView API 子集**操作，不直接碰控件：

`Add / Delete / Modify / GetText / GetParent / GetChild / GetNext / GetPrev / GetCount / IsExpanded`

因此**重写只发生在视图层**，逻辑层零改动。

### 1.3 交互耦合点（重写必须兼容）

- **命中测试**：`_HitTest("MacroTree",coord)` → 桥接 `Query(MacroTree>HitTest:x;y)` 返回 `Tag|top/bottom|isExpander|originY|h`。左/右键、双击、拖拽插入线全吃它。
- **多选**：`ChkMark_<id>` 蓝✓ 标记（不是 WPF 选中态）。
- **选中**：`Modify(id,"Select")` → `SelectByTag`（滚动 + 焦点）。
- **展开/折叠**：WPF `TreeViewItem` 箭头原生切换 + `全部展开/全部折叠` 按钮。
- **调试标记**：⭐（调试起点）/→（当前位置）/🚫（跳过）/⎖（只读控制项）编码进节点文字。

### 1.4 桥接能力与限制（`Plugins/AHK-XAML/lib/dep/XAML_AHK_Bridge.cs`）

| 命令 | 现状 | 换 ListBox 的影响 |
|---|---|---|
| `AddXamlItem` | 支持 `ItemsControl/ListBox/Panel/ListBoxItem/ContentControl`（:4364-4456） | ✅ ListBox 可用 |
| `ClearItems` | `ItemsControl`/`Panel` 通用（:4609-4629） | ✅ 可用 |
| `SelectByTag` | **TreeView 专用**（:4470-4496） | ❌ 需加 ListBox 分支 |
| `HitTest` | **硬编码 TreeViewItem/TreeView**（:2707-2768） | ❌ 需加 ListBox 分支 |
| `IsOverTree` | **TreeView 专用**（:2770-2790） | ❌ 需加 ListBox 分支 |

**关键限制**：`AddXamlItem` 注入的是真实元素、桥接无 `ItemsSource` 数据绑定能力，WPF `VirtualizingStackPanel` 对真实元素不生效。因此「扁平列表」收益落地，**真·UI 虚拟化不做**（若未来超大宏需虚拟化，需给桥接新增 ItemsSource 绑定命令）。

### 1.5 可复用先例

- **列表 + 运行时注入卡片行**：`Gui/VarListenGui.ahk:157-367`（ListBox + `AddXamlItem` 注入 `<ListBoxItem>` 多列 Grid 行，斑马纹 `ListAltBg`）。
- **卡片样式**：`Gui/MacroGraph/MacroGraphNodeUI.ahk:1255`（Border 圆角+描边）、`:636-664`（阴影必须放内层 `DropShadowEffect`，父 Border 带阴影会裁子元素）。
- **主题色键**：卡片用 `DropdownBg`（底）/`InputStroke`（描边）/`TextMain`/`TextSub`/`Accent`/`ListAltBg`/`GraphConnSel`（选中描边）。

## 2. 目标架构

```
模型（不变）         视图（重写）
MacroEditNode 树 ──► 扁平卡片列表（仅展开节点，深度=缩进）
                     └─ ListBox 容器 + 运行时 AddXamlItem 注入 <ListBoxItem> 卡片
```

- 卡片结构：`ListBoxItem`（`Tag`=id）→ 阴影底板 `Border`（`DropShadowEffect`，`IsHitTestVisible=False`）→ 主体 `Border`（`DropdownBg` 底 + `InputStroke` 描边 + `CornerRadius(6)` + `Margin`=左缩进）。
- 卡片内容（单行，可扩展）：左侧展开箭头（有子节点才显示，命名 `Arrow_<id>`）→ 勾选标记 `ChkMark_<id>` → 图标 `Image` → 单行标题 `TextBlock`（命名 `Txt_<id>`）。未来要两行，在 `TextBlock` 外包 `StackPanel` 加副信息行即可。
- 命名元素沿用 `Txt_<id>`/`ChkMark_<id>`，保证 `Modify` 的增量更新与多选勾选逻辑不变。

## 3. 分阶段实施

### P1 视图层改平铺卡片（`Gui/MacroEditModel.ahk`）——核心

- `Render()`：递归遍历 `this.roots`，**只产出 `expanded==true` 的节点**，按深度算左缩进，生成扁平卡片序列；`ClearItems` 后逐卡 `AddXamlItem`。
- `_BuildNodeXml(node)` → `_BuildCardXml(node, depth)`：产出 `<ListBoxItem>` 卡片（结构见 §2）。
- `Modify(id,"Expand"/"Collapse")`：仍只改 `node.expanded` + `Render()`（展平重算）。`SetExpanded`（原同步 `Tvi_<id>`）改为 no-op 或删除。
- `_Select(id)`：改走 ListBox 版 `SelectByTag`（选中 + `ScrollIntoView`）。

### P2 桥接 C# 加 ListBox 分支（`Plugins/AHK-XAML/lib/dep/XAML_AHK_Bridge.cs`）

在现有命令里按 `ctrl is TreeView` vs `ctrl is ListBox` 分流，**沿用命令名**（改动面最小）：

- 新增 `CollectListBoxItems(ListBox)`：经 `ItemContainerGenerator` 遍历已实现的 `ListBoxItem` 容器（仿 `CollectTreeViewItems`）。
- `HitTest` 加 ListBox 分支：命中 `ListBoxItem` 返回 `Tag|top/bottom|isExpander|originY|h`；`isExpander` = 命中元素位于该卡左侧箭头区域（`Arrow_<id>` 或按左缩进 + 固定宽度 X 区间）且该节点有子节点。
- `SelectByTag` 加 ListBox 分支：遍历 `ListBox.Items` 按 `Tag` 匹配，`SelectedItem` + `ScrollIntoView`。
- `IsOverTree` 加 ListBox 等价：命中 `ListBox` 返回 `"1"`（内部按类型分流）。

改完删 `%TEMP%\AhkWpf\ahk-xaml.dll` 强制重编译（`XAML_FORCE_DYNAMIC_COMPILE` 只在 dll 缺失时编译）。

### P3 交互层适配（`Gui/MacroEditGui.ahk`）

- `_BuildAndShow()`：`view.Add("TreeView").Name("MacroTree")` → `view.Add("ListBox").Name("MacroTree")`（**沿用名字 `MacroTree`**，`_HitTest`/`Query`/`Modify("Select")` 调用点不改），补 `ScrollViewer` 滚动 + `Background/BorderBrush`。`DragInsertLine`、`MacroText` 保持。
- 展开箭头点击：`_ProcessTreeLeftClick` / `_OnTreeDoubleClick` 里 `parts[3]=="1"`（isExpander）分支改为「切换 `node.expanded` + Render」，不再依赖 WPF 双击展开/折叠。
- 删除 TreeViewItem 专属残留：`_RestoreNodeExpand`（`Tvi_<id>` 查询）、`_OnTreePreviewLeftDown` 里 `Query("Tvi_<source>>IsExpanded")`、`_OnTreeDoubleClick` 的「双击还原展开状态」逻辑（扁平列表双击只开编辑器，不折叠）。
- 拖拽 / 多选 / 右键 / 调试标记**不动**：仍走 `_HitTest` + 适配器 API + `ChkMark_<id>`，只要命中测试返回格式不变即可。

### P4 性能

- **只渲染展开节点**：塌陷分支不进入可视化树，是相对现状（全树序列化重建）的核心收益。
- **增量保留**：文本编辑、勾选、调试标记已走 `Txt_<id>`/`ChkMark_<id>` 增量，不动。
- 结构变更（增/删/移）首版仍全量展平 Render——展平后只含可见节点，体量远小于原全树。`ponytail: 若真机大宏仍卡，再对 Add/Delete 做单卡插入/移除（桥接需补 InsertItem/RemoveItem 按索引）`

---

## 4. 风险与决策

1. **桥接 HitTest ListBox 版（高）**：要复刻 TreeView 版的行间 Y 回退与展开箭头命中，最容易出错。**决策**：新增 `CollectListBoxItems` + 独立 ListBox 命中分支，不动 TreeView 旧路径，二者并存可回退。
2. **真·虚拟化不可得（已明确）**：桥接无 ItemsSource。扁平列表 + 只渲染可见节点已是收益上限，虚拟化后续需桥接新命令。
3. **展开箭头命中区域（中）**：卡片左缩进随深度变化，箭头 X 区间需按缩进推算。**决策**：箭头用命名元素 `Arrow_<id>`，命中测试沿可视树找 `Arrow_<id>` 判断，比纯 X 区间稳。
4. **测试手段（高）**：桥接依赖 `ahk-xaml.dll` + CLR，无法静态验证，必须真机双击 `RMT.ahk` 人工回归。

## 5. 验收标准

1. 打开含嵌套分支（如果 / 循环 / 如果Pro）的宏：逻辑树显示为卡片，缩进正确，展开箭头可折叠/展开，塌陷分支不显示。
2. 全部展开 / 全部折叠按钮正常。
3. 增删改插移、右键菜单（编辑/跳过/调试起点/插入/复制/粘贴/删除）、退格/清空/确定/应用并保存均正常且落盘正确。
4. 多选（Ctrl/Shift/单击）、复制删除；拖拽（左面板拖入、树内移动、插入位置提示线）正常。
5. 调试 F5/F6/⭐/→/终止：⭐起点、→当前位置高亮、单步推进、终止复位。
6. 双击卡片打开子编辑器、子编辑器模态（Owner 禁用）正常。
7. 文本模式与逻辑树模式切换、指令录制追加正常。
8. 明/暗主题下卡片配色、DPI 缩放正常。

## 7. 最终实现状态（超出原方案的增量优化）

原方案 P4 只做到「只渲染展开节点 + 全量展平」。真机回归后补了**真增量**，最终落点：

- **增删改插移换均增量，不整树/子树重建**：
  - `Add()` 可见时按扁平索引 `InsertXamlItem` 插单卡；`Delete()` 按 Tag `RemoveItem` 删卡。
  - 叶↔父转换（0↔1 子）只 `_UpdateArrow()` 改箭头文字，不重建（箭头恒占位命名 `Arrow_<id>_Txt`）。
  - 叶子操作不再 `RefreshTree`（视觉已由增量完成，`SaveCommandData` 只持久化）；分支结构变化才 `RefreshTree`（`GetChild != 0` / `isContainer` 守卫）。
- **桥接新增**：`InsertXamlItem`（`<index>|<xaml>` 插入）、`RemoveItem` 加 Tag 匹配、`HitTest`/`SelectByTag`/`IsOverTree` 加 ListBox 分支、`CollectListBoxItems`。
- **滚动条置顶修复**：WPF ListBox 默认 `VirtualizingStackPanel`，注入真实 ListBoxItem + `Items.Insert` 会触发虚拟化重算把滚动复位到顶。须 `VirtualizingPanel_IsVirtualizing("False")` + 注入 ListBoxItem Style 去默认内边距/选中高亮（照抄 VarListenGui）。
- **仍全量重建（仅结构变化）**：展开/折叠箭头点击、全部展开/折叠、首次 `InitTreeView`、改分支指令本身、清空容器、`OnSubNodeEdit`、多选删除、粘贴。
